================================================================================
1. RESUMEN EJECUTIVO
================================================================================

Sistema de HAR (Human Activity Recognition) heurístico sobre poses 2D
(8 keypoints upper-body). Sin machine learning en esta versión.

Flujo de producción:
  videos/<clase>/<CLIP>/user_XXX/poses_full.npy
       + meta.json (fps)
       ↓
  detect_action_json.py
       ↓
  output/<clase>/<CLIP>/user_XXX_poses_full_actions.json

El JSON contiene TODOS los estados y acciones detectados (sin filtro),
con timestamps, códigos de fiabilidad y metadatos.

6. PROGRAMA FINAL: detect_action_json.py
================================================================================

Qué hace:
  1. Resuelve el .npy bajo videos/
  2. Lee FPS de meta.json (o --fps)
  3. Ejecuta ActionAnalysisPipeline (todas las etiquetas)
  4. Escribe un JSON con todos los segmentos

Ejecución:
  cd /home/ignacio/Escritorio/Company/Tecnica_Heuristica_HAR

  # Clip por defecto
  python3 detect_action_json.py

  # Otro clip
  python3 detect_action_json.py 1/OTRO_CLIP/user_136/poses_full.npy

  # Forzar FPS
  python3 detect_action_json.py --fps 12.38

  # Imprimir por stdout
  python3 detect_action_json.py --stdout

  # Solo stdout, sin fichero
  python3 detect_action_json.py --stdout --no-save

  # Ruta de salida custom
  python3 detect_action_json.py -o /tmp/acciones.json

Opciones:
  npy                 ruta relativa a videos/ (opcional)
  --fps FLOAT         fuerza FPS
  -o / --output PATH  ruta exacta del JSON
  --output-dir DIR    raíz (default ./output); anida <clase>/<CLIP>/
  --stdout            imprime JSON por stdout
  --no-save           no escribe fichero
  --indent N          indentación JSON (default 2)

Salida por defecto:
  output/<clase>/<CLIP>/user_XXX_poses_full_actions.json

Mensajes de progreso van a stderr; el JSON puro puede ir a stdout.

7. FORMATO DEL JSON DE SALIDA
================================================================================

Estructura:

{
  "source": "<ruta absoluta al .npy>",
  "fps": 12.38,
  "fps_source": "<ruta meta.json | cli>",
  "num_frames": 370,
  "duration_s": 29.886914,
  "filter": null,                    ← null = sin filtro (todas)
  "num_segments": 44,
  "segments": [
    {
      "action": "ARM_EXTENDED_LEFT",
      "start_frame": 0,
      "end_frame": 40,
      "start": "00:00:00.000",
      "end": "00:00:03.312",
      "start_s": 0.0,
      "end_s": 3.312,
      "duration_s": 3.312,
      "code": 0,
      "feature": "elbow_angle_L",
      "reason": "...",
      "enter_threshold": 155.0,
      "exit_threshold": 140.0
    },
    ...
  ],
  "unsupported_2d": [
    {"action": "ARM_FORWARD_DEPTH", "code": 2},
    {"action": "ARM_BACKWARD_DEPTH", "code": 2},
    {"action": "HAND_FRONT_BACK", "code": 2},
    {"action": "TORSO_ROTATION_3D_EXACT", "code": 2},
    {"action": "SHOULDER_ANGLE_3D", "code": 2},
    {"action": "WRIST_DEPTH", "code": 2}
  ]
}

Notas:
  - Varios segmentos pueden solaparse (no es clasificación exclusiva).
  - code: 0=verde, 1=amarillo (heurística), 2=rojo (listado unsupported,
    nunca como segmento detectado).
  - Timestamps: frame i → t = i / fps → HH:MM:SS.mmm

10. ARQUITECTURA INTERNA (har_pose)
================================================================================

Pipeline:
  .npy
    → PoseSequence
    → FeatureExtractor (suavizado + geometría + derivadas)
    → StateDetector (histeresis → estados)
    → ActionDetector (FSM → acciones dinámicas)
    → SegmentProcessor (merge gaps + duración mínima)
    → JSON / TXT / UI

Módulos:
  config.py     KEYPOINTS, DetectionConfig, UNSUPPORTED_2D, rutas
  geometry.py   ángulos, distancias, lean (NaN-safe)
  filters.py    savgol / media / mediana + derivadas
  features.py   extracción de series temporales
  temporal.py   histeresis, merge, duración mínima
  detectors.py  StateDetector, ActionDetector, pipeline
  io_utils.py   load npy, fps, rutas, timestamps, escritura


================================================================================
11. KEYPOINTS Y GEOMETRÍA
================================================================================

KEYPOINTS (config centralizada):
  0 left_shoulder   1 right_shoulder
  2 left_elbow      3 right_elbow
  4 left_wrist      5 right_wrist
  6 left_hip        7 right_hip

Centros:
  Sc = media hombros
  Hc = media caderas
  C  = 0.65·Sc + 0.35·Hc     (pecho aproximado)

Escala corporal:
  scale = 0.55·ancho_hombros + 0.45·||Sc−Hc||
  floor min_body_scale = 1e-3

Ángulo codo: ángulo en codo del triángulo hombro–codo–muñeca [0,180°]
  ~180° ≈ extendido/recto

================================================================================
13. FILTRADO TEMPORAL Y FSM
================================================================================

Suavizado: savgol window=5, polyorder=2 (fallback media/mediana)
Histeresis: umbrales enter ≠ exit
Duración mínima: estados 0.20 s | acciones 0.12 s
Merge gaps: 0.12 s

Estados = persistencia (ej. ARM_EXTENDED_LEFT)
Acciones = transición FSM (ej. EXTEND_ARM_LEFT)
  No se etiquetan solo porque el vídeo empiece ya en el estado final.

17. QUÉ CALIBRAR
================================================================================

Alta prioridad:
  1. Ángulos de codo (extended / flexed / straight)
  2. Distancias muñeca–cintura / pecho
  3. Duraciones mínimas y merge_gap según FPS
  4. Deltas de acciones dinámicas

Media:
  5. Elevación / brazo abajo
  6. Ventana de suavizado

Baja (solo si usas CODE=1):
  7. Ratios frontal/perfil, cross_midline

Método: validar con validate_realtime_full / wrist_full → ajustar
DetectionConfig → regenerar con detect_action_json.py


================================================================================
18. LIMITACIONES
================================================================================

18.1 No hay profundidad 2D
  No se puede afirmar delante/atrás de un brazo, profundidad de muñeca,
  ni rotación 3D exacta del torso. Por eso CODE=2 no se detecta.

18.2 Perspectiva / foreshortening
  Ángulos y distancias 2D cambian con la cámara. CODE=1 es heurística,
  no medición 3D.

18.3 Calidad del .npy
  NaNs, oclusiones, errores de tracking YOLO se heredan.

18.4 Alineación vídeo–pose
  Si clip.mp4 y poses_full.npy difieren en nº de frames, la UI full
  puede desfasarse al final. El FPS incorrecto desplaza timestamps.

18.5 Sobredetección
  Muchas etiquetas pueden coexistir. Usar validate_* o el JSON filtrado
  para centrarse. No usar en producción crítica sin calibrar.

ADVERTENCIA FINAL
================================================================================

  CODE 0 → más defendible geométricamente
  CODE 1 → heurística de perspectiva (no 3D real)

Calibrar thresholds antes de uso serio.
