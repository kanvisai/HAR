1. DESCRIPCIÓN
--------------
Programa de detección heurística (sin machine learning) de estados y acciones
corporales a partir de secuencias de pose 2D almacenadas en archivos .npy.

Entrada:  .npy con shape (T, 8, 2) — frames × joints × (x, y)
Salida:   .txt con segmentos ACTION | START | END | DURATION | CODE
Directorio de datos (poses .npy):
  /home/ignacio/Escritorio/Company/Tecnica_Heuristica_HAR/videos/
  Estructura: videos/<clase 0-7>/<CLIP>/user_XXX/poses_full.npy

Directorio de salida por defecto:
  /home/ignacio/Escritorio/Company/Tecnica_Heuristica_HAR/output/<clase>/<CLIP>/

  Ejemplo de origen:
    videos/1/12Diciembre2025_..._002950_1/user_136/poses_full.npy
  Ejemplo de salida:
    output/1/12Diciembre2025_..._002950_1/user_136_poses_full_actions.txt

Validación in-situ (esqueleto + acciones en vivo):
  python3 validate_realtime.py
  python3 validate_realtime.py 1/CLIP/user_136/poses_full.npy --save-txt
  python3 validate_realtime.py --filter WRIST_NEAR



2. ARQUITECTURA
---------------
detect_actions.py          CLI de ejecución
har_pose/
  config.py                KEYPOINTS, DetectionConfig, clases CODE=2
  geometry.py              ángulos, distancias, inclinación (NaN-safe)
  filters.py               suavizado (savgol/media/mediana) + derivadas
  features.py              PoseSequence + FeatureExtractor
  temporal.py              histeresis, merge de gaps, duración mínima
  detectors.py             StateDetector + ActionDetector (FSM)
  io_utils.py              carga .npy, timestamps HH:MM:SS.mmm, escritura

4. CÓDIGOS DE FIABILIDAD
------------------------
  0  VERDE    Observable de forma razonablemente fiable en 2D
  1  AMARILLO Heurística dependiente de perspectiva (NO es 3D real)
  2  ROJO     No observable de forma fiable en 2D (unsupported_2d)

Clases CODE=2 (nunca se detectan; solo se listan al final del .txt):
  ARM_FORWARD_DEPTH
  ARM_BACKWARD_DEPTH
  HAND_FRONT_BACK
  TORSO_ROTATION_3D_EXACT
  SHOULDER_ANGLE_3D
  WRIST_DEPTH


5. FEATURES PRINCIPALES
-----------------------
  - Ángulos de codo (hombro-codo-muñeca), grados [0, 180]
  - Centros: hombros Sc, cintura Hc, pecho C = 0.65·Sc + 0.35·Hc
  - Escala corporal = 0.55·ancho_hombros + 0.45·altura_torso
  - Distancias normalizadas: muñeca→cintura/pecho/hombro, muñecas entre sí
  - Alturas relativas de muñecas (y_down = True, típico vídeo/OpenCV)
  - Orientación hombros/cintura, inclinación de torso, twist aparente
  - Dinámica: velocidades y derivadas temporales (tras suavizado)

5.1 PROXIMIDAD MUÑECAS → PECHO / CINTURA (CODE=0)
------------------------------------------------
Estados por lado:
  WRIST_NEAR_CHEST_LEFT / WRIST_NEAR_CHEST_RIGHT
      distancia(muñeca, centro_pecho) / escala  <  enter 0.40 (sale > 0.55)
  WRIST_NEAR_WAIST_LEFT / WRIST_NEAR_WAIST_RIGHT
      distancia(muñeca, centro_cintura) / escala <  enter 0.45 (sale > 0.60)
  WRIST_NEAR_TORSO_LEFT / WRIST_NEAR_TORSO_RIGHT
      cerca del pecho O de la cintura

Estados agregados:
  BOTH_WRISTS_NEAR_CHEST   ambas muñecas cerca del pecho
  BOTH_WRISTS_NEAR_WAIST   ambas muñecas cerca de la cintura
  ANY_WRIST_NEAR_CHEST     al menos una cerca del pecho
  ANY_WRIST_NEAR_WAIST     al menos una cerca de la cintura

Acciones dinámicas asociadas:
  WRIST_TO_CHEST_LEFT / RIGHT   acercamiento a pecho (FSM)
  WRIST_TO_WAIST_LEFT / RIGHT   acercamiento a cintura (FSM)


6. FILTRADO TEMPORAL
--------------------
  - Suavizado de coordenadas/features (Savitzky-Golay por defecto)
  - Histeresis (umbral de entrada ≠ umbral de salida)
  - Duración mínima de estado/acción
  - Fusión de gaps cortos de la misma etiqueta
  - Acciones dinámicas vía máquinas de estados (no solo frame final)

NO son universales. Deben calibrarse con un dataset real.

9. QUÉ CALIBRAR CON DATOS REALES
--------------------------------
  1. Ángulos de codo (extended / flexed / straight)
  2. Distancias muñeca–cintura / pecho / hombro
  3. Duraciones mínimas y merge_gap_s (según FPS del clip)
  4. Deltas de acciones (extend_delta, approach_delta, raise_delta)
  5. Ratios frontal/perfil (etiquetas CODE=1)
  6. Ventana de suavizado (smooth_window) según ruido del extractor


10. LIMITACIÓN FUNDAMENTAL 2D
-----------------------------
Un esqueleto 2D no tiene profundidad. No se puede afirmar con fiabilidad
si un brazo va hacia delante/atrás, ni medir rotación 3D real del torso.
Las etiquetas CODE=1 son heurísticas de perspectiva, no mediciones 3D.
Las CODE=2 no se inventan ni se estiman como fiables.
